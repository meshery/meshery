<p><strong>Uninstall exits with an error when the teardown is incomplete.</strong> Without <code>--force</code>, the command stops at the first failure: a rejected custom resource deletion, a failed Helm uninstall, a rejected custom resource definition deletion, or a namespace that is rejected or still present after the deletion timeout. Nothing after the failing step is attempted, so fix the underlying permission or API error and run the command again.</p>
<p>With <code>--force</code>, every cleanup stage is attempted even when an earlier one fails, and the command exits with a single error that lists each stage that could not complete. That makes <code>--force</code> the way to make progress on a cluster that only partially resists cleanup, but it also means a non-zero exit lists more than one cause: read the whole message before retrying.</p>
<p>Resources that are already gone (<code>NotFound</code>) count as successfully removed, so an interrupted or repeated uninstall is safe to run again. With <code>--keep-namespace</code>, the namespace is neither deleted nor waited on, and the command succeeds even when the namespace still holds Meshery resources.</p>
