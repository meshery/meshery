# Functional Specification: Meshery Support for kro ResourceGraphDefinitions (RGDs)

- **Status**: Proposed / Implemented (Phase 1: Core Kro Model & Component Registry)
- **Target Issue**: [meshery/meshery#13520](https://github.com/meshery/meshery/issues/13520)
- **Area**: `area/models`, `area/orchestration`
- **Related Project**: [kubernetes-sigs/kro](https://github.com/kubernetes-sigs/kro) (`kro.run`)

---

## 1. Executive Summary & Problem Statement

Cloud-native practitioners managing multi-resource topologies often face friction when orchestrating composite application architectures across Kubernetes clusters. **kro** (`kubernetes-sigs/kro`, Kuber-Resource-Orchestrator) addresses this by introducing `ResourceGraphDefinition` (RGD). An RGD empowers platform engineers to define custom, reusable APIs and DAG-based topologies using Common Expression Language (CEL) references. When applied to a cluster, the kro controller dynamically registers custom CRDs and reconciles the entire directed acyclic graph of underlying resources in dependency order.

To manage, design, and orchestrate kro-managed resources natively within Meshery, Meshery requires:
1. **First-class MeshModel support for kro**: Representing kro core constructs (`ResourceGraphDefinition`, `Graph`, `GraphRevision`) as first-class components in the Meshery Model Registry (`models/kro`).
2. **Dynamic Model & Component Synthesis**: Enhancing Meshery's Model Generator to recognize RGD custom schemas and generate transient or cluster-scoped Meshery Component definitions for instantiated composite kinds.
3. **Lifecycle Orchestration & Kanvas Integration**: Enabling visual composition, validation, and lifecycle management of RGDs and their topological relationships within Meshery Kanvas.

## 2. Background: Understanding kro Architecture

kro operates around three primary Custom Resource Definitions in the `kro.run` and `internal.kro.run` API groups:

| Kind | API Version | Scope | Role |
| :--- | :--- | :--- | :--- |
| **`ResourceGraphDefinition`** | `kro.run/v1alpha1` | Cluster | Declares the schema for a new composite resource and the graph of Kubernetes resources (Deployments, Services, ConfigMaps, Ingresses) instantiated per instance. |
| **`Graph`** | `kro.run/v1alpha1` | Namespaced | Represents the runtime execution graph and evaluation order of resources generated by a specific instance of an RGD. |
| **`GraphRevision`** | `internal.kro.run/v1alpha1` | Cluster | Internal controller representation tracking immutable version snapshots and hashes of an RGD. |

When an RGD is deployed:
1. The kro controller parses the `spec.schema` OpenAPI definitions and dynamically registers a new CustomResourceDefinition (e.g., `myapplications.kro.run`).
2. Platform users or Meshery deploy instances of `MyApplication`.
3. The kro controller resolves dependencies across nodes using CEL expressions (e.g., `${service.spec.clusterIP}`) and instantiates resources in topological order.

### 3.1 Static Model Representation (`models/kro`)
The static model establishes foundational support in Meshery:
- **Model Identity**: Name `kro`, Display Name `Kro`, Category `Orchestration & Management`, SubCategory `Scheduling & Orchestration`.
- **Schemas**: Exact OpenAPI v3 schemas extracted from `kubernetes-sigs/kro` core install manifests.
- **Visual Branding**: Brand SVG icons (color and monochrome white) with circle shape taxonomy.

### 3.2 Relational Model & Topological Graph
Two critical relationships govern kro within Meshery:
1. **Hierarchical Inventory (`hierarchical-parent-inventory-rgd-graph.json`)**:
   Defines `ResourceGraphDefinition` as a parent inventory container for runtime `Graph` instances.
2. **Non-binding Reference (`edge-non-binding-reference-graphrevision-rgd.json`)**:
   Connects `GraphRevision` snapshot references to the parent `ResourceGraphDefinition` via `spec.snapshot.name`.

## 4. Model Generator Workflow for RGDs

Meshery's Model Generator (`mesheryctl registry generate` and Server `/api/registry/register`) supports RGDs through the standard CSV integration pipeline:

```csv
registrant,modelDisplayName,model,category,subCategory,description,sourceURL,shape,primaryColor,secondaryColor
Github,Kro,kro,Orchestration & Management,Scheduling & Orchestration,kro ResourceGraphDefinitions,git://github.com/kubernetes-sigs/kro/main/manifests,circle,#2563EB,#60A5FA
```

When generating models from Kubernetes manifests containing `ResourceGraphDefinition`:
1. The generator extracts the CRD specifications for `ResourceGraphDefinition`, `Graph`, and `GraphRevision`.
2. Component definitions are written with `schemaVersion: components.meshery.io/v1beta2`.
3. Standard Meshery capabilities (workload configuration, styling, shape, relationship inspection, performance testing) are attached.
